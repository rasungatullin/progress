# Комплекс инженерного синтеза «Прогресс»

«Прогресс» — проект автономного инженерно-вычислительного комплекса для обработки внешних событий, структурного анализа, принятия решений, инструментального исполнения и верификации результатов.

## Назначение

Комплекс предназначен для координации вычислительных контуров, обеспечивающих выполнение инженерных задач в управляемой конфигурации. В составе комплекса языковые модели, интеграционные модули и исполнительные подсистемы рассматриваются как элементы единой вычислительной среды.

## Архитектурная схема

Базовая схема комплекса включает четыре ключевых контура:

- контур реакции на внешние события;
- контур интеграции с внешними системами;
- контур принятия решения;
- контур исполнения.

Внешний сигнал поступает в комплекс, проходит нормализацию и передаётся в контур принятия решения. Для согласования дальнейших действий используются данные интеграционных подсистем, оперативный контекст и проектное состояние. На первом прикладном треке контур должен уметь принять номер задачи, запустить кодирование, провести задачу через запрос на слияние и ревизию, вернуть замечания на доработку и довести цикл до слияния.

Каждый контур должен оставаться автономным модулем с простым внешним интерфейсом. Контуры могут обмениваться только формализованными запросами и результатами и не должны опираться на внутреннее устройство друг друга.

## Предполагаемые подсистемы

- подсистема опроса внешних систем и приёма сигналов;
- интеграционные модули поиска и получения данных;
- подсистема оперативного контекста;
- подсистема проектного состояния;
- координатор контуров;
- подсистема исполнения;
- подсистема верификации;
- подсистема конфигурации и журналирования;
- контекстный архив.

## Общий CLI

Комплекс имеет общий `CLI`, который выполняет две роли:

- запускает прикладные маршруты контуров как единый ручной вход в систему;
- позволяет запускать отдельные функции контуров изолированно, имитируя внешний сигнал или внутренний межконтурный вызов.

Такие режимы нужны для отладки, воспроизводимого разбора конкретного шага и локальной проверки маршрута без полного автономного цикла.

В сквозном виде CLI должен поддерживать:

- `dry-run` для режима, в котором внешние побочные действия не выполняются;
- `--explain` для вывода оснований, по которым были выбраны маршрут, профиль, ограничения и отдельные параметры;
- обязательное журналирование факта запуска каждого контура и модуля с их ключевыми параметрами.

## Пример CLI-вызова

```bash
progress synthesize --config ./configs/dev.yaml
```

Примерный режим вызова: загрузка конфигурации комплекса, активация контуров, подключение интеграционных модулей и запуск вычислительного каскада.

## Текущий статус

Проект находится на стадии первичного архитектурного оформления и начального прикладного проектирования. Ближайший практический приоритет состоит в фиксации рабочего цикла по задаче разработки: запуск по номеру задачи, кодирование, запрос на слияние, ревизия, доработка, повторная ревизия и слияние.

## Принципы терминологии

Документация проекта использует язык системной инженерии, автоматизированных контуров управления и вычислительных комплексов.

Принятые ориентиры:

- комплекс, подсистема, модуль, контур, каскад;
- инженерный синтез, структурный анализ, инструментальная обработка, верификация;
- оперативный контекст, проектное состояние, контекстный архив;
- координация, диспетчеризация, конфигурация, реконфигурация.

Проект сознательно не описывается как чат, бот, copilot или потребительское AI-приложение. Его предметная форма — автономный комплекс инженерного синтеза.
