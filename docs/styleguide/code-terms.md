# Кодовые и документационные термины

Имена Go-типов, JSON-полей, CLI-команд и внешних API сохраняются в коде без перевода. В документации рядом с ними используется закреплённое русское имя.

## Современные AI-концепции

При необходимости описания современных подходов следует использовать инженерные эквиваленты.

| Английский термин | Документационное имя |
| --- | --- |
| `agent` | автономный модуль |
| `workflow` | рабочий цикл |
| `orchestration` | координация подсистем |
| `memory` | контекстный архив |
| `planner` | контур планирования |
| `reflection loop` | контур верификации |
| `tool calling` | подключение инструментальных модулей |

## Термины исполнения и интеграции

| Английский термин | Документационное имя |
| --- | --- |
| `structured input` | структурированный ввод |
| `structured output` | структурированный вывод |
| `prompt` | исполнительная директива |
| `runner` | исполнительный модуль |
| `execution profile` | исполнительный профиль |
| `review` | ревизия |
| `review cycle envelope` | канонический конверт цикла ревизии |
| `reply to review` | ответ на замечание |
| `coder` | исполнительный каскад кодирования |
| `pull request` | запрос на слияние |
| `commit message` | сообщение коммита |
| `trailing block` | завершающий блок |
| `execution contour` | контур исполнения |
| `decision contour` | контур принятия решения |
| `integration contour` | контур интеграции |
| `reactivity contour` | контур реакции на внешние события |
| `runtime` | среда исполнения |
| `run record` | запись запуска |
| `launch` | запуск |
| `profile` | исполнительный профиль |
| `binding` | привязка ресурсов |
| `fallback` | резервный выбор |
| `issue` | задача, если речь идёт о рабочем объекте трекера; `issue`, если речь идёт о literal-объекте GitHub |
| `comment` | комментарий |
| `artifact` | артефакт |
| `provider` | адаптер интеграции |
| `route` | маршрут обработки |
| `signal` | сигнал |
| `context` | контекст |

Если английская форма требуется как literal-имя ключа, CLI-флага, тега, команды или иного программного интерфейса, она сохраняется без перевода. В описательном тексте приоритет всегда отдаётся русскому инженерному термину.

Если точный перевод невозможен, следует выбирать формулировку, которая сохраняет инженерный смысл и не переводит проект в лексику потребительских AI-систем.
