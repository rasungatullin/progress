# Публичные модели

Публичные модели межконтурного взаимодействия должны описываться через русское документационное имя и точное имя объекта кода, если речь идёт о реализации.

## Правила описания

Описание публичной модели должно содержать:

1. русское документационное имя;
2. точное имя Go-типа, JSON-поля или CLI-флага в обратных кавычках;
3. контур-владелец или контур-источник;
4. роль объекта в межконтурном обмене;
5. ограничения использования, если они влияют на другие контуры.

Например: `ExecutionPlan` — задание на исполнение, формируемое контуром принятия решения для передачи в контур исполнения. В тексте документации используется «задание на исполнение», а `ExecutionPlan` указывается только при прямой ссылке на Go-тип.

Описания таких моделей не должны ограничиваться перечислением полей. Для каждой публичной сущности требуется коротко указать, какой объект предметной области она представляет и как он называется в документации.

| `decision contour` | контур принятия решения | Управляющий контур выбора следующего режима обработки. |
| `integration contour` | контур интеграции | Контур унификации доступа к внешним системам. |

| `DecisionContext` | контекст решения | Сигнал и внешние сведения, по которым принимается решение. |
| `Decision` | решение | Тип обработки, причины и возможное задание на исполнение. |
| `DecisionReason` | основание решения | Зафиксированная причина выбора режима обработки. |
| `ExecutionPlan` | задание на исполнение | Межконтурная модель передачи задачи в контур исполнения. |

| `LaunchSpec` | спецификация запуска | Параметры непосредственного запуска исполнительного модуля. |
| `LaunchResult` | результат запуска | Статус, резюме, путь к сырому выводу и структурированный результат. |
| `StructuredInput` | структурированный ввод | Канонический входной контракт для контура исполнения. |
| `StructuredOutput` | структурированный вывод | Канонический выходной контракт результата исполнения. |
| `StructuredContext` | структурированный контекст | Именованный фрагмент проектного или оперативного контекста. |

| `StructuredQuestion` | структурированный вопрос | Вопрос, требующий ответа перед продолжением обработки. |
| `StructuredAction` | интеграционное действие | Нормализованное действие для следующего шага или внешней системы. |
| `StructuredChange` | описание изменения | Краткое описание выполненного изменения. |
| `StructuredCommand` | команда следующего шага | Команда или действие, передаваемые дальнейшей обработке. |
| `StructuredConclusion` | заключение | Итоговое заключение о состоянии результата. |

| `Allocation` | выделение ресурсов | Результат выбора исполнительного модуля, модели и привязки ресурсов. |
| `Workplace` | исполнительное рабочее место | Подготовленная среда исполнения. |
| `Request` | интеграционный запрос | Внутренний запрос к контуру интеграции. |

| `Response` | интеграционный ответ | Нормализованный результат контура интеграции. |
