## Словарь

| Термин | Значение |
| --- | --- |
| комплекс | Проект «Прогресс» как единая инженерно-вычислительная система. |
| контур | Автономная часть комплекса с собственной ответственностью и формализованным внешним интерфейсом. |
| контур реакции на внешние события | Контур регистрации внешних событий, нормализации сигналов и запуска последующего цикла обработки. |
| контур интеграции | Контур получения, изменения и нормализации данных внешних систем через внутренний контракт. |
| контур принятия решения | Управляющий контур, который по сигналу, контексту и ограничениям выбирает следующий режим обработки. |
| контур исполнения | Контур выполнения формализованной задачи в изолированной вычислительной среде. |
| вычислительный каскад | Последовательность действий, модулей и инструментальных вызовов, выполняемых для достижения результата. |
| исполнительный каскад кодирования | Прикладной вычислительный каскад, выполняющий изменения в кодовой базе. |
| ревизионный каскад | Прикладной вычислительный каскад проверки результата и формирования замечаний ревизии. |
| сигнал | Нормализованное сообщение о внешнем событии или внутреннем повторном запуске обработки. |
| задача | Рабочий объект трекера или внутренний объект обработки, который проходит через контуры комплекса. |
| задание на исполнение | Формализованное описание работы, передаваемое из контура принятия решения в контур исполнения. |
| решение | Результат работы управляющего контура: выбранный тип обработки, причины и возможное задание на исполнение. |
| маршрут обработки | Последовательность стадий обработки задачи. |
| оперативный контекст | Сведения, необходимые для текущего запуска и не являющиеся долговременной моделью состояния. |
| проектное состояние | Накопленное состояние проекта, используемое при принятии решения и верификации результата. |
| контекстный архив | Хранилище завершённых каскадов, состояний, артефактов и диагностических сведений. |
| структурированный ввод | Канонический входной JSON-контракт задачи для контура исполнения. |
| структурированный вывод | Канонический выходной JSON-контракт результата исполнения. |
| исполнительная директива | Итоговый текст запуска, собираемый контуром исполнения для исполнительного модуля. |
| исполнительный модуль | Внешний или внутренний механизм запуска вычислительного каскада. |
| исполнительный профиль | Преднастройка режима исполнения, требований к ресурсам, структурированному выводу и завершающим действиям. |
| привязка ресурсов | Правило выбора пары исполнительного модуля и модели. |
| исполнительное рабочее место | Подготовленная изолированная среда выполнения задачи. |
| запись запуска | Диагностический артефакт, фиксирующий вход, профиль, ресурсы, рабочее место и результат запуска. |
| запрос на слияние | Объект внешней системы для внесения изменений в основную ветку. |
| сообщение коммита | Краткое русское описание изменения, передаваемое в `git commit`. |
| замечание ревизии | Зафиксированное замечание по результату проверки. |
| ответ на замечание | Структурированный ответ на конкретное замечание ревизии. |
| заключение ревизии | Итоговая оценка готовности результата или необходимости доработки. |
| интеграционное действие | Операция чтения или записи во внешней системе через контур интеграции. |
| адаптер интеграции | Конкретный адаптер внешней системы, выбираемый диспетчером интеграции. |
| артефакт | Документ, файл, ссылка, результат запуска или иной объект, полученный либо созданный в процессе обработки. |
