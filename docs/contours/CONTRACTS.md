# Контракты межконтурного взаимодействия

## Назначение документа

Документ фиксирует проверенную карту обменов между контурами комплекса. Его задача — показать, какие контуры обмениваются данными, какой объект передаётся и какие инварианты не должны нарушаться при дальнейшем расширении реализации.

Каноническая кодовая карта находится в пакете `internal/contours`. Текущий документ является человекочитаемым описанием той же схемы.

## Правила межконтурного обмена

1. Контур обращается к другому контуру только через формализованный объект обмена.
2. Контур не должен зависеть от внутреннего устройства другого контура.
3. Внешние форматы не передаются за пределы контура интеграции как рабочая модель других контуров.
4. Задание на выполнение является согласованным шагом, а не предложением заново выбрать маршрут.
5. Журналирование и аналитика не являются источником текущего состояния рабочей задачи.
6. Очередь исполнения задач управляет допуском к запуску, но не меняет выбранное действие.
7. Контур пользовательского интерфейса оформляет эксплуатационные операции, но не принимает решение по задаче.

## Базовый цикл

| Источник | Получатель | Объект обмена | Смысл контракта |
| --- | --- | --- | --- |
| контур реакции на внешние события | контур интеграции | параметры восстановления данных | Событие превращается в запрос данных, но не в полное состояние задачи. |
| контур интеграции | контур принятия решения | каноническая задача и связанные объекты | Решение работает с нормализованной моделью, а не с внешними форматами. |
| контур принятия решения | контур исполнения | задание на выполнение | Исполнение получает уже согласованный шаг и не выбирает маршрут заново. |
| контур исполнения | контур принятия решения | результат выполнения | Следующий шаг выбирается новым рассмотрением после фиксации результата. |
| контур исполнения | контур интеграции | интеграционная операция | Внешние изменения проходят через нормализованный контракт интеграции. |

## Проверка

Пакет `internal/contours` содержит `DefaultRegistry` и метод `Registry.Validate`. Проверка гарантирует:

- все контуры целевой архитектуры описаны в реестре;
- у каждого контура указан пакет минимальной реализации и документ;
- каждый контракт ссылается только на известные контуры;
- каждый контракт содержит объект обмена, описание и инварианты;
- каждый контракт использует допустимый тип обмена;
- один и тот же обмен между двумя контурами не описан повторно;
- обязательные обмены базового цикла, отложенного запуска, методик, настроек, наблюдаемости и исследований присутствуют в реестре.

Проверка запускается общим тестовым набором `go test ./...`.
