# Очередь исполнения задач

## 1. Назначение

Очередь исполнения задач предназначена для управления задачами, по которым уже принято решение о выполнении, но фактический запуск должен быть отложен, приоритизирован или ограничен по числу попыток.

Её цель состоит в отделении принятого решения от запуска действия в условиях ограниченных ресурсов.

## 2. Краткое описание

Что получает на вход:

- ссылку на задачу;
- приоритет;
- время допустимого запуска;
- ограничение попыток;
- идентификатор задания на выполнение.

Что отдаёт на выход:

- элемент очереди;
- следующий готовый к запуску элемент;
- состояние после попытки выполнения.

Как работает:

- принимает элемент в состояние `queued`;
- выбирает готовый элемент с наибольшим приоритетом;
- переводит выбранный элемент в состояние `running`;
- после исчерпания попыток переводит элемент в состояние `manual-intervention`.

Чего не делает:

- не принимает решение о необходимости выполнения;
- не запускает исполнительный модуль;
- не меняет внешнюю задачу напрямую.

## 3. Основной состав

В состав подсистемы входят:

- элемент очереди;
- ссылка на задачу;
- правило приоритета;
- задержка запуска;
- счётчик попыток;
- состояние ручного вмешательства.

## 4. Практический каркас

Начальный каркас расположен в пакете `internal/executionqueue`.

Пакет содержит сервис `Service.Enqueue`, `Service.Next`, `Service.MarkAttempt` и типы `TaskRef`, `EnqueueRequest` и `Item`. Каркас использует хранение в памяти и задаёт контракт для будущего постоянного хранилища.
