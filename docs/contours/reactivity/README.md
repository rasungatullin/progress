# Контур реакции на внешние события

## 1. Назначение

Контур реакции на внешние события предназначен для регистрации изменений во внешней среде, нормализации входных сигналов и запуска последующего цикла обработки.

Этот контур является основой автономной работы комплекса, но не должен быть обязательным для ручного режима. Все остальные контуры должны сохранять работоспособность при ручной подаче сигнала через CLI или внутренний интерфейс диагностики.

## 2. Краткое описание

Что получает на вход:

- внешние события;
- webhook;
- результаты периодического опроса;
- сообщения о внешних изменениях.

Что отдаёт на выход:

- короткий нормализованный сигнал для контура принятия решения;
- минимальные метаданные сигнала: источник, тип, идентификатор объекта, время события.
- результат цикла обработки задачи при ручном или автономном запуске.

Как работает:

- наблюдает за внешними системами;
- выделяет значимые изменения;
- дедуплицирует и нормализует их;
- передаёт дальше только сигнал на обработку.
- в режиме обработки задачи восстанавливает задачу и связанный запрос на слияние через контур интеграции, запускает рассмотрение маршрута, передаёт выбранное задание в контур исполнения и меняет метки задачи по результату шага.

Чего не делает:

- не интерпретирует инженерный смысл задачи;
- не выбирает следующий шаг рабочего цикла;
- не запускает контур исполнения по существу задачи.

## 3. Основные функции

- периодический опрос внешних систем;
- приём webhook-событий;
- регистрация сообщений из очередей и служебных каналов;
- дедупликация сигналов;
- первичная классификация источника;
- нормализация события к внутреннему формату;
- формирование отложенных сигналов для повторного запуска обработки;
- генерация коротких внутренних сигналов для контура принятия решения, например в форме «обработать задачу X».

## 4. Входы и выходы

Входы:

- данные периодического опроса;
- входящие webhook-события;
- сообщения о смене состояния объектов;
- сигналы от внешних очередей и сервисов.

Выходы:

- нормализованный сигнал;
- первичные метаданные события;
- указание на источник сигнала;
- отложенный сигнал при необходимости повторной обработки.

## 5. Архитектурная роль

Контур обеспечивает реактивность комплекса и служит точкой входа для автономного вычислительного цикла.

Он не должен содержать логику принятия решения по существу задачи. Его ответственность ограничивается наблюдением, нормализацией и передачей сигнала дальше.

## 6. Практический каркас

Начальный каркас расположен в пакете `internal/reactivity`.

Пакет содержит сервис `Service.Normalize` и типы `Event`, `Process`, `Signal` и `Result`. Каркас сопоставляет внешнее событие с процессом реакции и возвращает нормализованный сигнал либо диагностируемое состояние `ignored`.

Практический обработчик задачи представлен методами `Service.ProcessTask` и `Service.RunTaskAction`.

`ProcessTask` принимает номер задачи и, при необходимости, имя маршрута обработки. На каждом цикле метод заново получает карточку задачи через контур интеграции, ищет открытый запрос на слияние с веткой по номеру задачи, передаёт контекст и имя маршрута в контур принятия решения и запускает выбранное действие контура исполнения. Если имя маршрута пустое, контур реакции не подставляет строку `default`; ссылку маршрута по умолчанию разыменовывает контур принятия решения. По умолчанию обработка повторяется, пока контур принятия решения не вернёт отсутствие следующей операции. Флаг CLI `--once` ограничивает запуск одним циклом.

`RunTaskAction` принимает номер задачи и явно выбранное действие. Рассмотрение маршрута пропускается, действие запускается один раз, а переход меток выполняется по тем же правилам, что и в полном цикле.

Закреплённые метки прикладного цикла:

- `Ожидает экспертизы` — ставится после первичного выполнения и после доработки;
- `Требует доработки` — ставится по итогам ревизии с замечаниями;
- `Экспертиза пройдена` — ставится по итогам положительной ревизии.

Для защиты от зацикливания `--max-cycles` задаёт предел циклов без полезного прогресса. Параметр `--max-total-cycles` задаёт отдельный аварийный предел всей обработки, включая результативные циклы; нулевое значение каждого параметра выбирает значение по умолчанию.

CLI:

```bash
progress reactivity process --task 123
progress reactivity process --task 123 --route pull-request-review --once
progress reactivity process --task 123 --max-cycles 20 --max-total-cycles 1000
progress reactivity action --task 123 --action review-pull-request
```
