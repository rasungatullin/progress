# Целевое архитектурное состояние контура реакции на внешние события

## Назначение

Контур реакции на внешние события является автономной входной частью комплекса. Он обнаруживает изменение во внешней среде, сопоставляет его с процессом реакции и формирует нормализованный сигнал для последующей обработки.

Контур не восстанавливает полную задачу, не выбирает инженерный шаг и не запускает действие по существу задачи. Его результатом является короткий сигнал, достаточный для обращения к контуру интеграции и дальнейшей передачи в контур принятия решения.

## Границы

Контур отвечает за:

- приём внешнего события;
- сопоставление события с процессом реакции;
- отбрасывание неподходящих или отключённых событий;
- нормализацию источника, вида события, типа объекта и внешнего идентификатора;
- передачу сигнала в следующий контур.

Контур не отвечает за:

- хранение полного состояния задачи;
- чтение связанных комментариев, запросов на слияние или документов;
- выбор маршрута обработки;
- выполнение действий и внешних операций записи.

## Основные сущности

Процесс реакции описывает, какие события интересуют комплекс и какой нормализованный сигнал должен быть сформирован при совпадении условий.

Внешнее событие содержит источник, вид события, тип объекта, внешний идентификатор и первичные метаданные. Оно может поступить из webhook, периодического опроса, очереди или ручного диагностического вызова.

Сигнал является межконтурным входом следующего шага. Он фиксирует источник, вид, процесс реакции, тип интеграции, тип объекта и внешний идентификатор.

В текущем каркасе этим сущностям соответствуют типы `Event`, `Process`, `Signal` и `Result` пакета `internal/reactivity`.

## Взаимодействие с другими контурами

### Контур интеграции

Контур реакции передаёт параметры, по которым нужно восстановить полные данные: тип интеграции, тип объекта, внешний идентификатор и сведения о процессе реакции.

Контур интеграции возвращает каноническую задачу и связанные объекты уже не в контур реакции, а в следующий участок обработки, заданный координацией комплекса.

### Контур принятия решения

Контур принятия решения получает сигнал и восстановленные канонические данные. Сигнал используется как причина рассмотрения, но не должен подменять собой полное состояние задачи.

### Контур журналирования и наблюдаемости

Каждое принятое, отклонённое или отброшенное событие должно фиксироваться как диагностическое событие с указанием процесса реакции и основания результата.

## Практический каркас

Пакет `internal/reactivity` содержит минимальный сервис `Service.Normalize`. Он проверяет процесс реакции, сопоставляет событие с процессом, формирует `Signal` либо возвращает диагностируемое состояние `ignored`.

Каркас предназначен для будущего подключения источников событий без изменения интерфейса остальных контуров.
