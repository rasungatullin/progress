# Контур пользовательского интерфейса

## 1. Назначение

Контур пользовательского интерфейса предназначен для эксплуатационного доступа к задачам, маршрутам, запускам, настройкам, ресурсам и диагностике комплекса.

Интерфейс должен делать работу комплекса проверяемой и управляемой, но не должен содержать собственную логику принятия решения.

## 2. Краткое описание

Что получает на вход:

- запрос на представление раздела;
- рабочую область;
- диагностические и эксплуатационные данные других контуров.

Что отдаёт на выход:

- модель представления;
- состав панелей;
- доступные эксплуатационные действия.

Как работает:

- проверяет запрошенный раздел;
- формирует заголовок и панели;
- добавляет действия просмотра или обновления;
- передаёт готовую модель внешнему интерфейсу.

Чего не делает:

- не принимает решение по задаче;
- не запускает действие без явного межконтурного запроса;
- не хранит собственную копию состояния внешних задач.

## 3. Основной состав

В состав контура входят:

- модель навигационных разделов;
- сборка эксплуатационного представления;
- связь с журналом запусков;
- связь с настройками и диагностикой;
- будущие ограничения по авторизации действий.

## 4. Практический каркас

Начальный каркас расположен в пакете `internal/ui`.

Пакет содержит сервис `Service.BuildView` и типы `ViewRequest`, `ViewModel`, `Panel` и `Action`. Существующая команда `progress web` остаётся локальным способом показа запусков исполнения, а пакет `internal/ui` задаёт контурную модель представления.
