# Целевое архитектурное состояние контура пользовательского интерфейса

## Назначение

Контур пользовательского интерфейса предоставляет эксплуатационную поверхность комплекса. Через него оператор должен просматривать задачи, маршруты, запуски, настройки, ресурсы, диагностические записи и результаты обработки.

Контур не должен становиться местом принятия решения. Он отображает состояние и оформляет явные эксплуатационные команды, которые затем проходят через соответствующие контуры и контур авторизации.

## Границы

Контур отвечает за:

- модель навигационных разделов;
- сборку представлений по данным других контуров;
- отображение диагностических записей и запусков;
- оформление эксплуатационных действий;
- передачу действий в контур авторизации и профильный контур.

Контур не отвечает за:

- выбор маршрута обработки;
- выполнение задания;
- изменение внешней системы напрямую;
- самостоятельное хранение актуального состояния задачи.

## Основные сущности

Запрос представления задаёт раздел и рабочую область.

Модель представления содержит раздел, заголовок, панели и доступные действия.

Панель группирует данные одного эксплуатационного назначения: запуски, маршруты, настройки, диагностику или сведения о рабочей области.

В текущем каркасе этим сущностям соответствуют `ViewRequest`, `ViewModel`, `Panel` и `Action` пакета `internal/ui`.

## Взаимодействие с другими контурами

### Контур журналирования и наблюдаемости

Поставляет события, записи запусков и диагностические сведения.

### Контур настроек и ресурсов

Поставляет сведения о доступных интеграциях, ресурсах, профилях и привязках.

### Контур авторизации

Проверяет право пользователя на просмотр сведений и выполнение эксплуатационных действий.

## Практический каркас

`internal/ui.Service.BuildView` формирует модель представления для разделов задач, маршрутов, запусков, настроек и диагностики. Каркас отделяет модель интерфейса от конкретного локального веб-сервера.
