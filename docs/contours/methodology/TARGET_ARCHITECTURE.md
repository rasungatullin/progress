# Целевое архитектурное состояние контура методик

## Назначение

Контур методик хранит переносимые способы прохождения задач через комплекс. Он описывает, какие маршруты, действия, операции и инструкции применимы к определённым классам задач.

Методика должна быть отделена от локальных ресурсов. Один и тот же маршрут может использоваться в разных проектах с разными исполнительными модулями, моделями, ограничениями доступа и интегрируемыми системами.

## Границы

Контур отвечает за:

- хранение маршрутов обработки;
- хранение сохранённых экземпляров действий;
- хранение инструкций для языковой модели;
- хранение расширяемых сущностей методики для смежных контуров;
- выбор методического элемента по запросу;
- фиксацию диагностических оснований выбора.

Контур не отвечает за:

- доступность ресурсов;
- авторизацию внешних операций;
- непосредственный запуск исполнительного модуля;
- чтение или запись внешних объектов.

## Основные сущности

Маршрут обработки задаёт последовательность проверок и связанное действие.

Действие в каталоге методик описывает сохранённый экземпляр: имя, класс, профиль, алиасы, признак необходимости рабочего места, а также набор операций, которые должен выполнить контур исполнения. Необходимость синтеза определяется составом операций действия.

Инструкция для языковой модели задаёт содержательную часть исполнительной директивы, но не заменяет действие и не управляет внешними операциями.

Каталог методик объединяет эти элементы и обеспечивает переносимость между проектами.

Расширяемая сущность методики `Entity` фиксирует вид сущности, имя, целевой контур и произвольный JSON `payload`. Эта модель нужна для случаев, когда смежный контур должен хранить новый методический элемент до появления специализированного Go-типа. Например, контур принятия решения может добавить сущность вида `decision-rule`, не меняя контракт маршрутов, действий и инструкций.

В текущем каркасе этим сущностям соответствуют `Catalog`, `Route`, `Action`, `Instruction`, `Entity`, `CatalogSnapshot` и `SelectionResult` пакета `internal/methodology`.

## Хранение и приоритеты

Каталог методик хранится двумя слоями:

- глобальный слой: `<progress-config-home>/methodology/`;
- локальный слой: `.progress/methodology/` в корне репозитория.

`<progress-config-home>` по умолчанию равен `${HOME}/.config/progress` и может быть переопределён через `PROGRESS_CONFIG_HOME`.

Внутри слоя корневой `catalog.json` хранит общий конфиг, включая `default_route`. Каждый методический объект хранится отдельным JSON-файлом в реестре своего вида: `routes/`, `actions/`, `instructions/` или `entities/`.

Для маршрутов, действий и инструкций файловый ключ совпадает с нормализованным `name`. Для расширяемых сущностей ключ задаётся как `<kind>--<name>`, потому что логический ключ сущности состоит из пары `kind/name`. Расхождение ключа файла и полей объекта считается ошибкой слоя.

Слои объединяются в порядке `global -> local`. При совпадении имён локальный маршрут, действие или инструкция заменяет глобальный экземпляр. Для расширяемых сущностей ключом пересечения является пара `kind/name`.

`CatalogSnapshot` возвращает объединённый каталог, список фактически прочитанных слоёв, источники каждой сущности и пути к глобальному и локальному каталогу.

Монолитный `catalog.json` со старыми массивами объектов поддерживается как миграционный входной формат. Операции `save` и первый `upsert` в старом слое записывают объекты в файловые реестры.

## Взаимодействие с другими контурами

### Контур принятия решения

Контур принятия решения использует контур методик для выбора маршрута обработки и действия, если эти сведения не зафиксированы непосредственно в локальном маршруте.

Для расширения правил рассмотрения без изменения базовой схемы контур принятия решения может читать `Entity` с собственным `kind`, например `decision-rule`, и интерпретировать `payload` как свою внутреннюю модель.

### Контур исполнения

Контур исполнения получает имя действия как часть задания на выполнение. Он не должен самостоятельно выбирать методику по внешнему состоянию задачи, но обязан сам разрешить это имя в сохранённое действие из каталога методик и декодировать запись в собственный тип `execution.Action`.

Семантика исполнения, валидация, нормализация и фактический запуск операций принадлежат контуру исполнения. Контур методик хранит только переносимую DTO-форму действия и не становится владельцем конкурирующей исполняемой модели.

### Контур настроек и ресурсов

Контур настроек и ресурсов указывает, какие профили, модели, исполнительные модули и переопределения доступны для выбранной методики в конкретной среде.

## Практический каркас

`internal/methodology.Service` реализует загрузку, слияние, просмотр, сохранение и выбор сущностей каталога. `Service.Resolve` загружает сохранённый каталог и выбирает маршрут, действие, профиль и инструкцию. `Service.Select` сохраняет прежний режим выбора из уже переданного каталога.

CLI `progress methodology` использует тот же сервисный контракт и не имеет отдельной логики хранения.
