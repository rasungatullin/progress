# Контур методик

## 1. Назначение

Контур методик предназначен для хранения и выбора переносимых описаний инженерного процесса: маршрутов обработки, действий, операций, инструкций для языковой модели и рекомендаций по применению исполнительных профилей.

Его цель состоит в отделении методического описания процесса от локальной доступности ресурсов, авторизации и конкретных внешних систем.

## 2. Краткое описание

Что получает на вход:

- запрос на выбор маршрута или действия;
- объединённый каталог методик;
- ограничения текущего рассмотрения.

Что отдаёт на выход:

- выбранный маршрут обработки;
- выбранное действие;
- подходящую инструкцию для языковой модели;
- диагностические сведения о выборе.

Как работает:

- находит маршрут по имени или выбирает маршрут по умолчанию;
- определяет действие, связанное с маршрутом;
- уточняет исполнительный профиль;
- выбирает инструкцию, совместимую с профилем.

Чего не делает:

- не проверяет доступность модели или исполнительного модуля;
- не обращается к внешним источникам;
- не выполняет действие.

## 3. Основной состав

В состав контура входят:

- каталог маршрутов обработки;
- каталог действий;
- каталог инструкций для языковой модели;
- правила выбора методического элемента;
- диагностический результат выбора.

## 4. Практический каркас

Начальный каркас расположен в пакете `internal/methodology`.

Пакет содержит типы `Catalog`, `Route`, `Action`, `Instruction`, `Entity`, `CatalogSnapshot`, `SelectionRequest` и сервис `Service`.

Сервис предоставляет:

- `Service.Load` — загрузку объединённого каталога методик;
- `Service.List` и `Service.Get` — просмотр сущностей каталога другими контурами и CLI;
- `Service.Resolve` — выбор маршрута, действия и инструкции из сохранённого каталога;
- `Service.Select` — выбор из уже переданного каталога;
- `Service.Save` — сохранение целого каталога в выбранный слой;
- `Service.Upsert` — добавление или обновление одного экземпляра сущности.

Каталог хранится двумя слоями:

- глобальный слой: `<progress-config-home>/methodology/catalog.json`, где `<progress-config-home>` по умолчанию равен `${HOME}/.config/progress` и может быть переопределён через `PROGRESS_CONFIG_HOME`;
- локальный слой: `.progress/methodology/catalog.json` в корне репозитория.

При загрузке глобальный слой применяется первым, локальный слой вторым. Если в слоях встречаются маршруты, действия, инструкции или расширяемые сущности с одинаковым именем, локальный экземпляр имеет приоритет.

Для расширения набора сущностей используется `Entity` — расширяемая сущность методики. Она содержит вид сущности `kind`, имя `name`, опциональный целевой контур `target_contour` и произвольный JSON `payload`. Например, контур принятия решения может добавить вид `decision-rule` без изменения базовой схемы маршрутов, действий и инструкций.

CLI доступен через `progress methodology`. Он позволяет просматривать, выбирать, сохранять и добавлять экземпляры сущностей каталога.
