# Разрешение конфликта запроса на слияние

## Назначение

Контур исполнения использует действие `resolve-merge-conflict` для открытого запроса на слияние с подтверждённым конфликтом. Действие подготавливает перебазирование, передаёт неслитые пути исполнительному модулю и принимает переписанную историю только после локальных проверок.

## Контракт

- Состояние: `Целевой контракт`.
- Вход: каноническая задача, запрос на слияние, базовая и рабочая ветки, внешнее состояние конфликта и настройки `git.push.allow-force-with-lease`.
- Результат: завершённое перебазирование и отправка через точный `--force-with-lease` либо диагностируемый отказ.
- Совместимость: обычная операция `rebase` без `allow_conflict` по-прежнему прерывает конфликт через `git rebase --abort`.

## Порядок запуска

Маршрутизация выполняется контуром принятия решения автоматически:

```text
открытый запрос на слияние + подтверждённый конфликт
    → resolve-merge-conflict
```

Исполнительный модуль изменяет только конфликтные файлы и возвращает структурированный результат. Контур исполнения получает неслитые пути, выполняет `git add` только для них и завершает перебазирование через `git rebase --continue`. Исполнительный модуль не выполняет операции Git и не отправляет ветку.

При подготовке рабочего места контур обновляет внешнюю ветку запроса на слияние. Локальные коммиты перебазируются на её актуальную вершину, если это возможно без конфликта. При конфликте этого вспомогательного перебазирования локальные коммиты отбрасываются, а внешняя вершина сохраняется как приоритетная. После подготовки рабочего места операция разрешения конфликта выполняет только основное перебазирование на базовую ветку.

## Диагностика

Операция отказывает при грязном рабочем месте, неожиданной ветке, запрещённой политике `--force-with-lease`, оставшихся неслитых путях, незавершённом перебазировании, неуспешном структурированном заключении или конкурентном изменении удалённой ветки. При отказе задача не переводится в состояние `Ожидает экспертизы`.
