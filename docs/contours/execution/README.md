# Контур исполнения

## 1. Назначение

Контур исполнения предназначен для выполнения формализованной и изолированной задачи, подготовленной контуром принятия решения.

## 2. Основной состав

В состав контура входят:

- диспетчер исполнения;
- исполнительные профили;
- подсистема ресурсного снабжения;
- исполнительные рабочие места.

## 3. Основные функции

- выбор исполнительного профиля по типу задачи;
- контроль требований к среде, ресурсам и доступам;
- резервирование ограниченных ресурсов;
- подготовка исполнительного рабочего места;
- нормализация structured input и сборка итогового prompt для вычислительного каскада;
- запуск вычислительного каскада;
- разбор structured output и возврат результата в пригодном для дальнейшей автоматической обработки виде;
- фиксация промежуточных и итоговых результатов;
- передача результата в верификационный контур.

## 4. Внутренние элементы

### 4.1 Диспетчер исполнения

Диспетчер исполнения агрегирует исполнительные сущности, резервирует ресурсы и проводит задачу до завершения.

### 4.2 Исполнительный профиль

Исполнительный профиль задаёт способ выполнения задачи определённого класса, требования к ресурсам, среде, доступам и завершающим действиям.

### 4.3 Подсистема ресурсного снабжения

Подсистема ресурсного снабжения хранит сведения о доступных внешних ресурсах, квотах, бюджетах и конфигурационных пресетах, а также выполняет предварительное резервирование.

### 4.4 Исполнительное рабочее место

Исполнительное рабочее место представляет собой подготовленную и воспроизводимую вычислительную среду: каталог, репозиторий, контейнер или иную изолированную конфигурацию исполнения.

В базовой реализации CLI рабочее место может подготавливаться как локальный `git worktree` в каталоге `.progress/workplaces/<name>`. Такое рабочее место создаётся от актуальной default branch удалённого `origin`, получает локальную ветку `<name>` и при повторном вызове с тем же именем переиспользуется только в том случае, если каталог остаётся валидным `git worktree` на ветке `<name>`.

### 4.5 Нормализация structured input и output

Контур исполнения работает не только с текстовым заданием, но и со структурированным контекстом задачи. Назначение structured input состоит в том, чтобы передать в вычислительный каскад полноценный контекст исполнения: постановку, ограничения, предысторию, замечания, ожидаемые артефакты и иные сведения, пригодные для программной сборки итогового prompt.

Контур исполнения сам определяет, в каком виде представить эти данные вычислительному каскаду. Он может:

- собрать итоговый prompt из текстовой части и структурированного контекста;
- добавить описание ожидаемой структуры structured output;
- адаптировать форму этих инструкций под выбранный исполнительный профиль.

После завершения вычислительного каскада контур исполнения обязан выделить structured output из ответа, распарсить его и вернуть результат в нормализованном виде. Основное назначение structured output состоит в том, чтобы результат можно было передавать в другие контуры и интеграции без повторного смыслового разбора свободного текста.

Такой результат может использоваться для:

- прикрепления замечаний ревью к коду через интеграционные модули;
- передачи рабочему каскаду структурированного списка доработок и ответов на комментарии;
- передачи команд следующему шагу, например на открытие pull request;
- передачи заключений, например о необходимости доработок или о допустимости завершения цикла.

## 5. Архитектурная роль

Контур исполнения обеспечивает непосредственное проведение задачи через набор инструментальных и вычислительных модулей без самостоятельного изменения целевой постановки.

## 6. Дополнительная документация

Для разгрузки настоящего обзора детальные материалы вынесены в отдельные документы:

- `docs/contours/execution/STRUCTURED_IO.md` — structured input/output, поток данных и правила расширения механизма;
- `docs/contours/execution/CLI.md` — структура команд `cobra`, схемы вызовов и роли CLI-команд контура исполнения.
