# Контур принятия решения

## 1. Назначение

Контур принятия решения предназначен для определения дальнейшего режима обработки по поступившему сигналу, доступному проектному состоянию и данным из внешних систем.

Это управляющий контур, который восстанавливает текущее состояние прохождения задачи по данным внешних систем и правилам рабочего цикла и координирует переходы между стадиями обработки.

## 2. Краткое описание

Что получает на вход:

- короткий сигнал;
- правила рабочего цикла и маршрутизации;
- данные из внешних систем через контур интеграции.

Что отдаёт на выход:

- решение о следующем шаге;
- задание для контура исполнения, если нужен исполнительный шаг;
- список действий для контура интеграции, если нужны внешние изменения.

Как работает:

- по сигналу запрашивает через интеграции нужные внешние факты;
- восстанавливает текущую стадию рабочего цикла;
- определяет тип задачи и допустимый следующий шаг;
- при необходимости запускает исполнение и затем инициирует внешние действия.

Чего не делает:

- не хранит собственное долговременное состояние жизненного цикла задачи;
- не реализует внутренности интеграционных адаптеров;
- не выполняет содержательную работу вместо контура исполнения.

## 3. Основные функции

- классификация сигналов;
- атрибуция задачи и уточнение её инженерного типа;
- анализ ограничений;
- определение дефицита сведений для принятия решения;
- запрос дополнительной информации через интеграционные модули;
- выбор сценария обработки;
- формирование задания на исполнение;
- запуск контура исполнения по сформированному заданию;
- интерпретация структурированного результата исполнения;
- выполнение последующих действий во внешних системах через контур интеграции;
- принятие решения об отложенной обработке, ожидании или отклонении;
- маршрутизация задачи по вычислительным каскадам исполнения.

## 4. Входы и выходы

Входы:

- нормализованный сигнал;
- проектное состояние;
- оперативный контекст;
- данные интеграционных модулей;
- конфигурационные ограничения.

Выходы:

- решение о режиме обработки;
- приоритет задачи;
- указание на отложенное выполнение или отклонение;
- задание для исполнительного контура;
- запрос дополнительного контекста;
- интеграционные действия следующего шага;
- набор действий, которые должны изменить внешнее состояние задачи или связанных объектов.

## 5. Архитектурная роль

Контур принятия решения является управляющим звеном вычислительного цикла. Его задача состоит в согласовании конкретного режима обработки для разных типов задач, внешних систем и исполнительных профилей.

Важное ограничение: контур не должен брать на себя внутреннюю реализацию интеграционных адаптеров или исполнительных движков. Он работает только через опубликованные интерфейсы смежных контуров.

Контур также не должен быть самостоятельным долговременным хранилищем жизненного цикла задачи. Источником истины для статусов, комментариев, связанных запросов на слияние и иных признаков процесса остаются внешние системы, а контур решения лишь восстанавливает текущую стадию обработки на момент запуска.

## 6. Первый прикладной приоритет

На первом прикладном этапе контур должен быть ориентирован на замкнутый цикл задачи разработки:

1. запуск по номеру задачи;
2. передача задачи в кодирующий каскад;
3. открытие запроса на слияние;
4. запуск ревизии и постановка замечаний;
5. передача замечаний на доработку и повторная ревизия;
6. слияние запроса при положительном заключении ревизии.

После стабилизации этого цикла контур должен быть расширен режимами проверки готовности задачи к исполнению и синтеза подробного описания.

Типичные действия по результату исполнения на этом этапе:

1. повторно запустить исполнение с новыми ограничениями или замечаниями;
2. оставить комментарий во внешней системе;
3. передвинуть объект по статусу;
4. завершить цикл положительным заключением.
