Контур пользовательского интерфейса

Отчёт о контуре эксплуатационного просмотра настроек, маршрутов, задач, запусков и диагностических сведений.

Пакет: internal/ui Документация: docs/contours/user-interface Класс: обеспечивающий контур
К основному отчётуК каноническому описанию

Назначение

Контур пользовательского интерфейса должен показывать состояние комплекса, диагностические записи и доступные эксплуатационные действия. Он не должен содержать собственную логику принятия решения по задаче.

Схема контура

Сущности и роли

СущностьРоль
ViewRequestЗапрос представления по разделу и фильтру.
ViewModelЗаголовок, панели и действия эксплуатационного представления.
PanelБлок данных пользовательского интерфейса.
ActionДоступная эксплуатационная операция.

Как работает сейчас

  1. internal/ui содержит минимальный сервис построения модели представления.
  2. progress web запускает локальный интерфейс на основе активов internal/cli/web_assets.
  3. Фактический web-интерфейс ориентирован на просмотр записей запусков исполнения.

Проблемы и вопросы

  • В UI-материалах есть раздел «Верификация», которого нет в реестре контуров.
  • Есть устаревшие ссылки на Profile.commit_push.
  • Нужно связать интерфейс с наблюдаемостью, а не напрямую с переходной историей исполнения.
