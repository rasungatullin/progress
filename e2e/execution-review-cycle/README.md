# E2E-прогон цикла исполнения и ревизии

Каталог фиксирует повторяемый сквозной прогон контура исполнения по маршруту:

1. создание локальной канонической задачи через параметры `--task-number`, `--title` и `--task`;
2. первичная реализация с подготовкой `git worktree`, запуском стендового исполнительного модуля, разбором структурированного вывода, коммитом и отправкой ветки;
3. ревизия результата с блокирующим замечанием;
4. доработка по замечанию ревизии с повторным коммитом и отправкой той же ветки.

Тест не обращается к GitHub и не использует реальные языковые модели. Вместо этого он создаёт временный bare-репозиторий, временный рабочий репозиторий, локальные файлы `.progress` и стендовый бинарник `opencode` в `PATH`.

В текущем срезе контур исполнения трактует номер канонической задачи как обязательную `head_ref`-ветку для всех действий. Чтобы сценарий оставался повторяемым до исправления [задачи #129](https://github.com/rasungatullin/progress/issues/129), тест заранее создаёт ветку задачи `101` от `main`.

Проверяется, что контур проходит через профиль, ресурсное снабжение, подготовку исполнительного рабочего места, запуск исполнительного модуля, нормализацию структурированного вывода и `commit-push`. Дополнительно проверяется, что диагностические файлы `.progress/runner-output` и `.progress/execution-runs` не попадают в отправленную ветку.

Запуск:

```sh
go test ./e2e/execution-review-cycle
```
